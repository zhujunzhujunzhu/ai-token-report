# 发布检查与事故恢复

发布包为 `dsh-token-report`（CLI）与 `dsh-plugin-token-report`（DSH 插件）。

## 发布入口

```bash
bun run publish:plugin:dry    # 全部验证 + 打包 + 真启动 + dry-run，不上传
bun run publish:plugin:next   # 全部验证通过后发布 next
bun run publish:plugin        # 全部验证通过后发布 latest
bun run publish:cli:dry
bun run publish:cli:next
bun run publish:cli
bun run publish:dry           # 两个包共同验证、dry-run
```

以上全部进入 `scripts/release.ts`，无跳过验证的参数。不要直接在 dist 执行 `bun publish`，那会绕过仓库检查。
脚本默认 dry-run，只有显式 `--publish` 才上传；未知参数及 `--publish --dry-run` 都报错。
任一步失败或超时，后续发布不会执行。

每次生成 `.artifacts/releases/<时间>/report.json`、逐步日志和 tarball，记录 SHA-256。
解包验证后发布同一个 tarball，不再重新构建。next 已发布的同版本不能再次上传 latest；应通过 registry dist-tag 提升版本，或增加版本号重新验证。

## 必备环境

Bun、真实 Node ≥22.15、已安装的兼容 DSH、tar、真实会话日志、开发 MySQL。
`ATR_NODE_BIN` 可指定 Node，`ATR_DSH_MODULES` 可指定 DSH 宿主 node_modules，
`ATR_MYSQL_URL` 可指定测试库，`DSH_HOME` 指定日志来源。默认 MySQL 为本机开发实例 3335 / ai-token。
缺少环境会中止，不能把没有执行的检查当成通过。

## 自动验证范围

| 环节 | 验证内容 |
|---|---|
| 全仓测试、typecheck、两个 Web 构建 | 单元、HTTP 契约、权限、查询、实际资源 |
| identity / ingest / admin / report-ingest E2E | 真 HTTP 与投递全链路 |
| DB parity / driver parity | 固定真实日志副本的 SQL 与直扫；Bun 与 Node；不改正在使用的本地库 |
| MySQL dialect / portal parity / Node mysql2 | 方言活体、双后端逐字段对账、真实 Node 驱动 |
| 本地与部门 Web 验证 | SSR、SVG 布局几何、图表（不依赖运行中的预览页或硬编码 Chrome 路径） |
| 两个 npm verify | 清单、Node 真实加载、CLI 双运行时 HTTP |
| 插件分层验证与 SQL | HTTP、Cordis 代理、解析、浏览器产物、SQL/降级 |
| bundles 检查 | zod 不进入前端产物 |
| 插件实际 tarball | 真 Loader 干净安装、重复 ID 复现、升级修复、备份/幂等/配置保留、浏览器信封执行、完整 DSH Web HTTP |
| CLI 实际 tarball | 解包后重新跑双运行时验证，禁止重建掩盖漏文件 |
| 发布 | 校验 SHA-256，上传已验证文件 |

`diagnose-boot`、`probe-activation`、`repro-boot-failure` 是针对用户环境的排障工具；
发布时使用临时 profile 的 `verify-profile-boot.ts`，不对真实用户 profile 启动或修改。
需要真实模型凭证的付费会话不在自动发布中运行。

## 0.3.0 事故与恢复

症状是 `duplicate loader entry id: token-report`，整个 DSH 启动失败。
`dsh plugin add` 会自动登记 bundle，bundle 会插入 `token-report`。
旧的手动 insert、重复 bundle、源码包与发布包并存都会导致重复挂载。
此前验证覆盖 import 和单插件 Context，遗漏 profile 合并与完整宿主启动，发布入口也未强制串联检查。

0.3.1 的离线 `repair-profile.mjs` 默认只检查，`--apply` 才写入，先备份再把旧 insert 转成 ID 覆盖，去掉源码包依赖及 bundle。冲突不猜测、不落盘；不访问身份、数据库、日志或 outbox。具体恢复命令见插件 README。

修复后的约束：bundle 是插件 insert 的唯一来源；用户配置只使用 `- id: token-report` 覆盖。
`config` 是整体替换，人工合并时必须保留原有上报设置。

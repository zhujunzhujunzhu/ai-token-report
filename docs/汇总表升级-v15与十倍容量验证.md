# 汇总表 v15 与十倍容量验证

2026-10-08 已完成实现、真实数据压测、线上 v14 → v15 迁移及部署。目标是当前约 42 万条事件增长到约 420 万条时，常用全年页面仍可响应。结果覆盖当前数据分布和 16 路并发；没有承诺任意维度增长、冷缓存或无限并发都亚秒。

## 3. 汇总结构与精确性

实现：`packages/core/src/db/portal-schema-v15.ts`、`cube.ts`、`portal.ts`、`query.ts`；金额分布运算在 `packages/shared/src/price.ts`。旧 v8 汇总保留兼容，本节结构用于新查询。

- `usage_cube` 保留 UTC 小时、本地日/时段/工作日、来源、稳定成员、旧身份快照、原始供应商/模型、项目路径及会话。四个 token 列分别求和，`reasoning` 单存。会话仍按原身份键 `DISTINCT`，跨格不会重复相加。
- 不存金额。保留计价时段分类和四类 token 除以 1000 的稀疏余数分布，用原金额函数还原逐事件取整。换价、基础价/专属价、闲时价、多币种、未计价均沿用原契约；价目变化无需重新汇总。
- `usage_cube_dirty` 由事实表 INSERT/UPDATE/DELETE 触发器在同一写入事务标记，更新同时标记旧/新小时。重复主键失败、回滚不会留下虚假更新；提交顺序倒置不会被时间水位漏掉。
- 补齐先锁脏小时，再建立事实表读快照；删除旧格、写新格、删除脏标记在一个事务提交。迟到上报等待该锁后重新置脏。默认每批 24 小时，上限 64；启动后台追齐，之后每 30 秒补齐；停服务等待当前批并取消后续批。
- 查询在**同一 SQL 快照**拼接「有效且干净的汇总格」与「脏小时、窗口两端不足整小时、非整小时换价边界的原始事件」。不存在脏格和原始事件双计。时区/时段版本键不符时整个查询回退原始表，后台重建派生物。
- 来源、成员与数据范围下推；供应商/模型、项目规则和分组多对多继续按查看者及现有规则在查询期解析。保留未归属与旧身份视图，权限没有扩大。明细原值仍查事实表。
- 尾部访问使用新增小时表达式索引，MySQL 由 `LATERAL ... WHERE (ts DIV 3600000)=hour ... LIMIT` 保证按小时索引查找；简单 JOIN 或动态时间范围在实测计划中会退化全扫，已经撤掉。空尾部索引查找约 0.02–0.04ms。
- 同数据库身份、筛选、SQL/参数或趋势计算参数及完整价目快照的在途聚合可共用；最多 64 个任务，完成/失败即删除。没有 TTL 缓存；权限、价格和其他成员筛选不会串结果。

新增三表、两个事实索引、三个事实触发器均进入 v15 受控定义与摘要。完整门禁检查触发器内容和小时索引表达式、可见性、非唯一属性等；缺失/漂移拒绝启动或 resume，不会自动补成另一份结构。

另修正迁移指纹分页：对于二进制排序且无尾空格的事件主键，使用主键 keyset 分页，保持原哈希序列和旧列集合。其他历史排序方式保留旧路径。避免对 42 万行反复 `ORDER BY BINARY ... OFFSET` 排序；线上只读核对新旧哈希相同，约 3.2 秒完成。

## 5. 迁移、部署与回滚

部署报告：`.artifacts/perf-2026-10-08/cube-release/.artifacts/deploys/2026-10-08T14-03-36-661Z/report.json`。

实际顺序为「验证/打包/preflight → 全库备份 → 停 PM2 → 显式迁移 → apply → schema/运行时/公网资源核验 → 后台补齐 → HTTP 验收」。Bun 运行时、公网健康与资源均通过，使用 `--keep-old-assets` 保留旧标签页资源。

生产开启 binlog，应用连接虽有 TRIGGER 权限，MySQL 仍拒绝 CREATE TRIGGER，要求管理员权限。第一次尝试因此自动还原 v14。最终只在离线迁移子进程使用受保护的管理员连接；没有给应用授予 SUPER，也没有修改 `log_bin_trust_function_creators`。管理员口令/数据库 URL 不写日志。

迁移前 gzip 全库备份：

```text
/root/atr-backup-20261008-v15.sql.gz
SHA256 b12fbacadd920b673b77f9c12c0631f3e50c37e00186539ed46dd9c334a56d21
```

旧服务端、门户、启动脚本：`/data/ai-token-report/.cube-v15-backup-20261008-v15`；状态：`/root/.atr/cube-v15-state.json`；普通部署备份另在 `/data/ai-token-report/.deploy-backup-2026-10-08T14-03-36-661Z`。这些保留，不随测试清理。

**schema 已为 v15，不能只回滚到 v14 服务端产物。** 需要停服务、删除本轮新增的三个触发器/三张派生表/两个索引、删除 v15 账本行并恢复版本 14、再还原匹配的旧产物。回滚控制器保留在受保护的 `/root/.atr/cube-v15-control.mjs`，从服务器执行：

```bash
node /root/.atr/cube-v15-control.mjs status
# 只有确需回滚时执行；会停止服务、还原 schema 与旧产物，然后重启。
node /root/.atr/cube-v15-control.mjs rollback
```

该回滚只删除新增派生物，不用旧备份覆盖事实表，因而保留升级后正常收到的事件。完整备份仅作为额外恢复手段。状态文件与控制器路径检查限定本次固定备份；跨版本的新部署之后应重新制定回滚，不直接复用本控制器。

本次压测容器 `atr-cube-perf-8f5c78c7` 及其全部临时 schema、线上临时导出和探针均已清理；已有开发数据库容器未动。备份、回滚状态、控制器和验证日志保留（`cube-cleanup.txt`）。

观察项：健康 `schema_version=15`；`usage_cube_dirty` 正常可能有当前小时 1 条，不能要求持续为零；大量脏小时应随后台批次下降。定期查看汇总格/事实行比例与占用、不同筛选整屏延迟、补齐耗时；若会话/项目维度显著膨胀，再评估更紧凑的分层汇总。当前压测说明有容量余量，不能把 512MiB buffer pool 当成永久容量上限。

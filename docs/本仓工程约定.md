# 本仓工程约定

> 本文是 `repo-conventions` skill 的完整版文档，面向**人**阅读与评审。
> skill 版本在 `.agents/skills/repo-conventions/SKILL.md`，两者内容对应，
> 改一处要同步改另一处。
>
> 本文只讲**怎么写**（工具链 / 目录 / 命名 / 注释 / 依赖）。
> **写什么**（口径 / 日志解析 / 身份）各有专门文档，见 §8。

## 0. 五条铁律

| # | 规则 | 违反了会怎样 |
|---|---|---|
| 1 | 只用 **`bun`**，绝不用 `npm` / `yarn` / `pnpm` | 装出不同的依赖树，`bun.lock` 与 `node_modules` 打架 |
| 2 | 测试用 **`bun test`**，不引入 vitest / jest | 多一套配置与 transform，且与 `Bun.serve`、zstd 等原生能力对不上 |
| 3 | **改口径必须同改 `packages/shared/test/metrics.test.ts`** | 实测结论（94.3% / 19.3 倍）失去防线，两端口径悄悄漂移 |
| 4 | **提交前 `bun test && bun run typecheck` 两者都必须过** | typecheck 是契约漂移的唯一拦截点，跳过它等于等运行时看空图表 |
| 5 | **代码注释一律中文**，注释解释「为什么」而不是「做什么」 | 见 §6 |

### 为什么是 bun 而不是 npm

这不是「换个包管理器」的偏好问题，而是**换运行时**：

| 依赖的 Bun 原生能力 | 用在哪 |
|---|---|
| `Bun.serve` | 本地服务与部门服务端（含 `idleTimeout`） |
| `Bun.file` | 静态资源托管 |
| `bun test` | 全仓测试运行器 |
| `bun build` | DSH 插件打包（`--target=node --format=esm`） |

`bunfig.toml` 里还配置了 `exact = true`（精确锁版本）与仓内缓存目录 `.bun-cache/`。

## 1. 常用命令

```bash
bun install
bun test                        # 全仓：7 个文件 / 168 个测试
bun run typecheck               # 7 个包，每个都必须 exit 0
bun run build                   # web-local + web-portal 两个 web

bun test packages/shared        # 只跑单包
bun run --filter '@ai-token-report/server' test

bun run stats -- --period today # 终端统计
bun run web                     # 本地页面（需先 bun run build:local）
bun run --filter '@ai-token-report/server' start   # 部门服务端 → 8787/api/health
bun run dev:local               # web-local 开发服务器
bun run dev:portal              # web-portal 开发服务器

# MySQL 方言活体验证（需要本机可连的 MySQL；只建/删 probe_* 探测表）
ATR_MYSQL_URL='mysql://user:pass@127.0.0.1:3306/ai_token_report' bun run --filter '@ai-token-report/core' verify:mysql
```

### 1.1 包过滤与参数转发

| 目的 | 写法 |
|---|---|
| 跑某个包的脚本 | `bun run --filter '@ai-token-report/server' test` |
| 从根脚本转发参数 | **必须带 `--`**：`bun run stats -- --period today` |

⚠️ `bun run stats --period today` **不会**把参数传给 CLI。根脚本本身是
`bun run --filter '@ai-token-report/cli' start`，参数会被 bun 自己吃掉，
表现为「参数没生效但也不报错」。这类静默失效最难排查，所以根脚本一律用 `--` 转发。

### 1.2 退出码约定

写脚本或计划任务时要认这些码：

| 命令 | 退出码 |
|---|---|
| `dsh-token` 统计 | `0` 成功 / `1` 找不到会话目录 / `2` 参数错误 |
| `dsh-token web` | `0` 正常停止 / `1` 静态产物缺失或启动失败 / `2` 参数错误 |
| `dsh-token report` | `0` 成功（含 dry-run、本轮无新增）/ `2` 参数错误 / **`3` 投递失败** |

`report` 的 `3` 是**刻意与 `2` 分开**的：计划任务据此判断「该重试」还是「配错了」。
把两者合并会让「网断了」和「token 写错了」在日志里长得一模一样。

## 2. 目录与包职责

| 路径 | 职责 | 一句约束 |
|---|---|---|
| `packages/shared` | **契约单一真源**：上报 DTO、查询响应、口径公式 | ★ **不得依赖任何运行时** |
| `packages/core` | 内核：decode / scanner / aggregate / range / state / format / types / home / identity-store | 只依赖 `shared`；**HTTP 投递不在 core** |
| `packages/cli` | 命令入口：`cli.ts` / `deliver.ts` / `report.ts` | 用户唯一入口 |
| `packages/server` | 上报接收 + 本地直查 + 部门统计 + 静态托管 | 一个 server 两副面孔 |
| `packages/web-local` | 本地页面（`/api/local/*`） | 独立构建、独立部署 |
| `packages/web-portal` | 部门看板（`/api/v1/stats/*`） | 独立构建、独立部署；**每个请求都要身份 token** |
| `packages/dsh-plugin` | DSH 插件 | 实时上报 + 界面用量面板；**不得碰 `this.#私有字段`** |

### 2.1 依赖方向不可逆

```
shared  ←  core  ←  cli
   ↑        ↑       ↑
   └────────┴───────┴── server / web-local / web-portal / dsh-plugin
```

- **`shared` 必须零运行时依赖** —— 它要同时跑在浏览器、Bun 与 DSH 插件进程里。
  想给它加 `node:fs` / `node:zlib` 之前先问：前端也用得上吗？
- `core` 只依赖 `shared`。
- `cli` 依赖 `core` + `shared` + `server`（`--web` 要内嵌服务）。
- 新增跨包 import 前确认**没有成环** —— 环会让 `tsc` 与 `bun build` 表现不一致。

### 2.2 关于旧目录

迁移期旧目录 `dsh-token-stats/`、`frontend/`、`p0-verify/`、`dsh-session-inspector/`
**已全部删除**。`ARCHITECTURE.md` 提到它们时是在讲历史。

`frontend/` 只剩 `node_modules` / `dist` 残留空壳，**不在 workspace 内、勿改**。

## 3. 测试约定

### 3.1 位置：`<pkg>/test/*.test.ts`

测试与被测代码**同包**，不集中到根目录的 `test/`。当前 7 个文件：

| 文件 | 覆盖 |
|---|---|
| `packages/shared/test/metrics.test.ts` | ★ 口径公式与实测结论 |
| `packages/core/test/core.test.ts` | 解码 / 扫描 / 聚合 |
| `packages/core/test/identity-store.test.ts` | 身份文件原子写入与降级 |
| `packages/cli/test/incremental.test.ts` | 增量水位线 |
| `packages/server/test/identity.test.ts` | 凭证表与校验 |
| `packages/server/test/local-api.test.ts` | 本地直查路由 |
| `packages/dsh-plugin/test/identity.test.ts` | 插件侧身份解析 |

### 3.2 端到端脚本不是 `bun test` 文件

`packages/server/test/e2e-identity.ts` **由 `bun run` 执行**，不是测试文件：
它真的起两个 HTTP 服务（部门 + 本地）跑完整署名链路，
用 `console.log` 打印 `✅ / ❌` 并自行 `process.exit`。

⚠️ **别把端到端脚本命名为 `*.test.ts`** —— `bun test` 会捡走它，
让它被当成单元测试并发跑起来，去抢 `18787` 这类固定端口，结果随机失败。

### 3.3 人工验证脚本放 `<pkg>/verify/`

`packages/web-local/verify/` 下有 `verify-data.ts` / `verify-render.ts` /
`verify-layout.ts` / `verify-charts.ts`，用

```bash
bun run --filter '@ai-token-report/web-local' verify
```

触发。它们**不进 CI，也不该被当成回归测试** —— 渲染与图表需要人眼判断。

### 3.4 断言要固化「为什么」

口径测试断言的不是随便一个数，而是实测结论：

```ts
// 好的断言：写清这个数从哪来、错了会怎样
expect(cacheHitRate(sample)).toBeCloseTo(0.943, 3) // 9845 条样本实测 94.3%
```

改公式时**必须同步改断言**，否则它从「防线」退化成「噪音」，
下一个人会选择把它删掉 —— 那才是真正的损失。

## 4. 类型与字段命名

### 4.1 snake_case / camelCase 的边界

| 场景 | 命名 | 例 |
|---|---|---|
| DB 列 / HTTP 线上字段 | **`snake_case`** | `cache_read_tokens` |
| TypeScript 内存类型 | **`camelCase`** | `cacheReadTokens` |
| 本地身份文件（JSON） | `camelCase` | `createdAt` / `updatedAt` |

**转换只发生在边界**（服务端落库 `ingest.ts`、前端取数 `web/src/api/`）。
内核一律 camelCase —— 内核里混进 snake_case，会让「这个字段是线上的还是内存的」
彻底说不清。

### 4.2 tsconfig 是逐包的

7 个包**各自**一份 `tsconfig.json`，**没有 `extends` 公共基础**。
共同点（`strict` / `verbatimModuleSyntax` / `noEmit` / `noUncheckedIndexedAccess`）
靠手工保持一致。

⚠️ **跨包 import 靠各包 `paths` 显式映射**，例如 `packages/cli/tsconfig.json`：

```jsonc
"paths": {
  "@ai-token-report/shared": ["../shared/src/index.ts"],
  "@ai-token-report/core":   ["../core/src/index.ts"],
  "@ai-token-report/server": ["../server/src/index.ts"]
}
```

**新增跨包 import 就要在用到它的那个包加一条 paths**，否则 `tsc --noEmit`
报找不到模块，而 `bun` 运行时却跑得通 —— 这种「运行时对、类型检查错」的落差
最容易被误判成工具链坏了。

`verbatimModuleSyntax: true` 带来两条硬性要求：

1. **纯类型导入必须写 `import type`**，否则会被当值导入保留下来；
2. 相对 import **一律带 `.js` 后缀**（`from './deliver.js'`），即使源文件是 `.ts`。

### 4.3 `noUncheckedIndexedAccess` 是打开的

数组/下标访问的静态类型是 `T | undefined`，写 `arr[i].foo` 会编译失败。
要么 `arr[i]!`（有把握时），要么先判空。

这是刻意的：本仓大量解析外部 JSON 与 zstd 帧，下标越界是真实风险，不是理论洁癖。

## 5. 依赖管理

- `bunfig.toml` 的 **`exact = true`**：新增依赖锁精确版本，**不要改成 `^`** ——
  版本漂移会让不同机器算出不同的数。
- 包间引用一律 **`workspace:*`**：
  ```jsonc
  "dependencies": { "@ai-token-report/core": "workspace:*" }
  ```
- **不要为一个小工具引入第三方包**。已实测 zstd 用 `node:zlib` 原生支持即可，
  不需要第三方 zstd 包（见 `会话日志解析` 文档）。
- 依赖缓存固定在仓内 `.bun-cache/`，便于离线与 CI 复用。

### 新增依赖前先过三问

1. **Bun / Node 原生能做吗？** 能就别加（zstd、HTTP、SQLite 都是原生）。
2. **`shared` 要用它吗？** `shared` 的任何依赖都会传染给前端与插件。
3. **它进热路径吗？** 插件 `emit()` 是**同步热路径**，加任何包都要掂量。

### 已有的第三方运行时依赖（先例，别重复引第二套）

| 包 | 位置 | 为什么它通过了三问 |
|---|---|---|
| `vue` / `chart.js` / `vite` | `web-local` / `web-portal` | 界面与图表不可能原生手写；不进任何热路径 |
| `@deepseek-ai/schemastery` / `chart.js` / `react-day-picker` | `dsh-plugin` | 插件宿主生态自带；schema 用于配置 |
| **`hono`（4.13.9，精确锁版）** | **`server`** | S12 引入。① 原生**不能**替代：Bun/Node 只提供「起服务」，路由/中间件/405/body 上限都要自己写（原先手写了 185 行分发 + 31 处错误信封 + 3 份鉴权映射）；② `shared` **不用**它，只在 server 与插件宿主半；③ 不进热路径（`dsh-plugin` 的 `emit()` 与它无关）。**它被 `bun build` 内联进发布产物，因此 npm 包仍是零运行时依赖**（`verify:npm` 断言这点） |
| **MySQL：不引入任何依赖** | `core/src/db/mysql.ts` | 部门上报库的第二个后端走 **Bun 内建 `Bun.sql`** —— 第 1 问（能不能原生）答案是「能」，所以不加包。⚠️ **Node 上配 MySQL 会明确报错**（Node 无内建 MySQL 客户端），这是刻意的：npm 版 CLI 只跑本机 SQLite，为用不到的通路引 `mysql2` 会进发布产物。见 `docs/mysql上报库.md` |

> ⚠️ **不要引入 `@hono/node-server`**：实测它在 Bun 上 import 即崩
> （详见 `docs/server架构重构方案.md` §3.5 与 §6 的已知问题）。

## 6. ★ 中文注释约定

**本仓最显眼的风格要求：所有代码注释用简体中文。**

### 6.1 写「为什么」，不写「做什么」

反面教材（复述代码，等于噪音）：

```ts
// 遍历 records
for (const rec of records) { ... }
```

本仓要的写法（解释动机与后果）：

```ts
// 扫描过程中文件被删除是正常竞态：这一轮先忽略它，
// 下一轮的指纹自然不含该文件，会触发重扫。
continue
```

判断标准：**删掉这行注释，下一个改代码的人会不会踩坑？**
会 → 写；不会 → 别写。

### 6.2 文件头要有模块说明

每个源文件顶部都有一段块注释，说明**这个文件在整个平台里的位置**。
复杂文件不止一段 —— `packages/server/src/index.ts`、`local-api.ts`、
`packages/core/src/decode.ts` 的头部注释本身就是该模块的设计文档。

### 6.3 三个必须标出来的标记

| 标记 | 用在 | 例 |
|---|---|---|
| `★` | 关键不变量、核心决策 | `★ 这是身份可信边界的落点` |
| `⚠️` | 反直觉、易踩的坑 | `⚠️ 必须显式设置，否则默认值是 10 秒` |
| `🚨` | 硬约束，违反即事故 | `🚨 emit() 在同步热路径，只能入队` |

### 6.4 「不要修」的注释

对**刻意为之的反直觉实现**，注释要明确写「这是刻意的，不要修」。本仓已有若干处：

| 位置 | 反直觉之处 |
|---|---|
| `GET /api/local/identity` | **绝不返回 token**（不发回浏览器） |
| 身份校验失败 | 返回 **`200 + ok:false`，不是 401** |
| `cacheHitRate` 分母为 0 | 返回 **0 而非 NaN** |
| `cacheLeverage` 的 `input === 0` | 返回 **0 而非 Infinity** |

这些看起来都像 bug。**没有注释，下一轮重构就会把它们「修」掉**，
然后线上出现一个查不出原因的空图表或误导性错误提示。

### 6.5 什么时候保留英文

保留原文的是：**标识符、日志原文、错误信息、协议 / API 名**
（`Bun.serve`、`ECONNRESET`、`event_id`、`ON CONFLICT DO NOTHING`）。
这些翻译了反而搜不到。

## 7. 提交前自检

```bash
bun test && bun run typecheck
```

两者都必须过：`bun test` 全绿 + **7 个包全部 exit 0**。

| 检查项 | 为什么 |
|---|---|
| `bun test` 全绿 | 677 个测试里有口径断言，红了就是口径漂了 |
| `bun run typecheck` 7 包全过 | ★ 契约漂移的主要拦截点。前后端字段对不上时它**直接编译失败**，而不是等运行时看到空图表 |
| 改了 web 源码 | 还要 `bun run build`，并**刷新页面确认**（被托管的是构建产物） |
| 改了 `shared` 的字段 | 两端 typecheck 都会红 —— 这是设计如此，别用 `as any` 绕过 |

### 当前基线（2026-09 实测）

```
bun test          → 677 pass / 0 fail / 29 files
bun run typecheck → 7 个包全部 exit 0（shared / core / server / cli / web-local / web-portal / dsh-plugin）
```

界面上摸不到、但**必须单独跑**的几条（都需要外部服务或会写构建产物）：

```bash
bun run packages/server/test/e2e-{ingest,admin,identity}.ts     # 真 HTTP：35 / 54 / 27 项
bun run packages/server/verify/verify-mysql-portal.ts           # 双后端逐位对账（需 MySQL）：53 项
bun run --filter '@ai-token-report/core' verify:mysql           # MySQL 方言活体（需 MySQL）：17 项
bun run --filter '@ai-token-report/shared' verify:bundles       # zod 没进三份前端产物：4 项
bun run build:npm:cli && bun run verify:npm:cli                 # 发布产物双运行时（Node + Bun）
```

改动后若这两个数字变了，先确认是不是**预期内**的变化，
再决定要不要同步更新本文与 `AGENTS.md`。

> ⚠️ 本机环境变量 `HTTP_PROXY` 末尾带 LF（实测），会让**任何由 Node 执行的**
> 工具链在求值 `node:http` 时崩掉（`ERR_PROXY_INVALID_CONFIG`）——
> 表现是 `bun run typecheck` 直接起不来。临时绕过：跑之前清掉该变量。
>
> ⚠️ 在 pwsh 里 `bun … 2>&1 | Select-Object -First N` 有两个坑：
> ① 会把 bun 的 stderr 当错误记录，**虚报 exit 1**（真实退出码要单独取）；
> ② `-First N` 会**掐断管道并杀掉 bun**，留下半清理状态影响下一次运行。
> 看长输出用 `-Last N`，或先重定向到文件（`cmd /c "bun test > out.txt 2>&1"`）。

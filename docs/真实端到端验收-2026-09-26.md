### 真实插件 outbox：断网、宿主重启与确认丢失

补做一次真实模型调用，安装的是最终验收 tarball `0.3.1`（SHA256 与本报告一致）。真正 Node DSH headless 在接收端端口关闭时生成 `session-dbf6b2d2-9d19-4ff1-8a5d-db232f60d051:14`，四项用量为 **7,491 / 2 / 0 / 0**。模型进程正常退出后，真实插件磁盘 outbox 仍保留这条事件，事件 ID 及原始用量与模型日志一致；恢复前 MySQL 为零条。

删去两份临时模型配置后，启动另一个真正 Node DSH Web 进程，不调用模型、不手调 `emit()`、不借助 CLI 投递，由插件生命周期自动读取原 outbox。受控转发器把原始请求转给 19876，MySQL 首次接受 1 条；测试故意不把成功确认交还插件，outbox 仍为 1 条。恢复确认后，插件再次投递只计重复 1 条，才清空 outbox。

MySQL 的稳定人员 ID、首次凭证 ID、首次接收时刻及四项用量在重放前后完全相同。两次真实宿主进程及临时转发器均已停止，保留真实日志、原 outbox 字节快照及 SHA256，未改变正式测试服务或原用户配置。证据：`.artifacts/v4-real-plugin-outage.json`。本项把真实模型事件与插件故障恢复连接成同一条链，仍不包含浏览器展示验收。

# 真实端到端验收记录（2026-09-25）

> 本文保留文件凭证架构阶段的原始记录。新版数据库 v4 的实施与真实链路结果见 [2026-09-26 验收记录](./真实端到端验收-2026-09-26.md)，不复用本文旧架构数量作为新版验收结论。

目标：真实 DSH 模型调用产生计费事件，分别通过插件与 `dsh-token-report` CLI 上报，再核对服务端数据库、查询接口与部门网页。所有本轮测试数据均在隔离环境中生成，不改用户生产凭证和历史上报库。

## 验收层次

1. 基线与故障回归：单元测试、类型检查、网页构建和组件渲染。
2. 服务端实际监听与数据库：Bun/Node HTTP、身份与后台登录、SQLite/MySQL。
3. 真实采集端：DSH 宿主实际模型调用、插件自动上报、CLI 实际进程读取真实会话日志。
4. 网页实际操作：网页登录、查询、明细与采集事件数值核对。

单测、注入事件及人工构造请求只作为边界故障检查，不作为第 3、4 阶段的通过证据。

## 已定位的问题

- CLI 未使用已有身份文件，未署名时仍可能扫描并尝试上报。
- 上报客户端把无效的成功响应当作完整确认；部分拒收时不能凭条数推断哪条记录成功。
- 插件 outbox 写入失败时清空队列，存在数据丢失风险。
- 插件满批入口同步进入写盘与请求，停机也可能未等正在执行的投递完成。
- 服务端 `port: 0` 未返回操作系统分配的实际端口，Bun 与 Node 都受影响。
- 405 响应的访问日志误记为 404。
- MySQL 对账脚本的 SQLite 对照组继承环境变量后也可能连接 MySQL，导致对账失去意义。

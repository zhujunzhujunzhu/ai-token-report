# 时间范围切换优化（2026-09-27）

## 根因与修改

实际 Web profile 中的 `localDb: false` 覆盖了默认开启的 SQLite 增量库，每个未缓存范围都会重新解压扫描全部日志。
运行中的 HTTP 请求已确认 `source: scan`，并非推测。将这项显式配置改为 `true` 后，Web 的配置热加载生效，接口返回 `source: local-db`，无需终止 DSH 进程。

浏览器原先只保存一份成功响应，切回刚看过的范围仍显示更新中。本轮增加按范围、维度和页码区分的成功快照缓存：

- 30 秒有效期，最多 32 项 / 2 MiB，最近使用的快照优先保留。
- 有效快照同步展示，取消旧请求；迟到响应不能覆盖已切回的范围。
- 跨日、观察到不同数据代次或手动刷新时清空缓存；不缓存失败响应或缺少代次的旧协议。
- 轮询、前台恢复与手动刷新仍真实取数，命中缓存不会延后兜底检查，保留对其他进程新增日志的发现能力。
- 缓存未命中时保留原内容和范围标签；失败不会把原范围数字标成新范围。

同时纠正 `config.ts` 中仍声称“默认 false”的过期注释。没有修改统计口径、日志解析或事件去重规则。

# 把本插件收录进 DSH 插件市场（提交物与步骤）

> 目标：让 `dsh-plugin-token-report` 出现在 DSH「设置 → 插件市场」的**发现**页，
> 用户能一键安装。本文是这次收录的**提交物 + 操作手册 + 验收清单**，
> 事实依据来自 2026-10-04 实测（市场 `dshmarket@1.66.8`、精选列表仓库源码）。

---

## 1. 先看清链路：市场没有「官方审核」

| 环节 | 是什么 | 谁决定 |
|---|---|---|
| 设置里的「插件市场」 | 社区插件 **dshmarket**（`dsh-market/dsh-market`，dshmarket.com） | 第三方，与 DeepSeek 官方无关 |
| 卡片数据 | 每次打开实时拉 `https://awesome-dsh-plugin.com/plugins.json` | 站点由精选列表仓库 CI 生成 |
| **收录动作** | 往 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 提 PR，**加一个 YAML 文件** | 该仓库维护者评审后合并 |
| 生效 | 合并后站点自动重建，市场通常一天内可见 | 自动 |

市场 README 原话：「这个仓库是市场应用本身，不是插件目录……请去 awesome-dsh-plugin 提 PR」。
所以**唯一要做的投稿动作就是那一个 YAML**。

## 2. 提交物（一个文件）

放进 awesome-dsh-plugin 的 **`data/plugins/`** 目录：

**文件名**：`zhujunzhujunzhu__ai-token-report--packages-dsh-plugin.yml`

```yaml
url: https://github.com/zhujunzhujunzhu/ai-token-report/tree/main/packages/dsh-plugin
name: zhujunzhujunzhu/ai-token-report#dsh-plugin
category: usage
description:
  en: 'Token usage panel for DeepSeek Harness: a bar above the composer opens billing token totals, trend charts, per-model and per-project breakdowns and a custom date range, read from local session logs of DSH, Codex, Claude Code, Trae and WorkBuddy. With a self-hosted portal URL and an app key it also reports usage events to that portal; with neither configured it collects nothing. It exposes token_usage tools plus a ctx.tokenReport service, and never collects conversation content.'
  zh: 'DSH 的 token 用量面板：输入框上方一条用量条，点开是计费总量、趋势图、按模型/项目/来源的分组明细与自定义日期范围，数据来自本机 DSH / Codex / Claude Code / Trae / WorkBuddy 的会话日志；填了自建服务端地址与 appKey 后，用量事件会实时上报到那个服务端，两者都没配时一个字节都不采集；另提供 token_usage 工具与 ctx.tokenReport 服务。不采集对话内容。'
```

**注意**：

- `description` 里含 `: `（冒号加空格）必须加引号 —— 上面已经加了。
- **不要**写 `npm:` 字段：映射由站点自动探测，手写会被校验拒绝。
- 一个 PR 最多 3 条；只加自己这一条，不要动别人的条目。
- 分类取值表里有 `usage`（站点上显示为 Usage & Billing），正是本插件的位置。

## 3. 站点怎么认到 npm 包（决定了包名不能解耦）

站点脚本 `scripts/probe-npm.mjs` 对每条目的 `url` 做这件事：

```js
const sub = repoPath.includes('/tree/') ? repoPath.split('/tree/')[1].replace(/^[^/]+\//, '') : null
const pkg = await fetchJson(`https://raw.githubusercontent.com/${repo}/HEAD/${sub ? sub + '/' : ''}package.json`)
const name = pkg.name                       // ← 直接读**被收录子目录**里的包名
// 要求 registry 上存在该包，且它的 repository 指回本仓
```

⇒ **`packages/dsh-plugin/package.json` 的 `name` 必须等于已发布的 npm 包名**
（这就是 0.9.0 把仓内包名从 `@ai-token-report/dsh-plugin` 改成 `dsh-plugin-token-report` 的原因）。
不一致时映射为空，市场会把「一键安装」退化成源码安装
（`github:…#path:/packages/dsh-plugin`）—— 而本仓源码包依赖 `workspace:*`，那条路**装不上**。

## 5. 发布新版 + 提 PR 的顺序（不能反）

站点与市场读的是**仓库 HEAD** 与 **npm registry**，所以：

```bash
# ① 全量验收（发布前必跑；先构建再跑 verify，verify 装的是 dist）
bun run typecheck && bun test
bun run --filter 'dsh-plugin-token-report' build
bun run packages/dsh-plugin/verify/verify-plugin.ts          # 79 项
bun run packages/dsh-plugin/verify/verify-cordis-load.ts     # 11 项 ★ 与官方 OTel 共存
bun run packages/dsh-plugin/verify/verify-resolution.ts      # 7 项
bun run packages/dsh-plugin/verify/verify-client-bundle.ts   # 40 项
bun run build:npm:plugin && bun run verify:npm:plugin        # 真 Node 装载
bun run publish:plugin:dry                                   # 只断言 tarball，不发布

# ② 真发布：先 next 再 latest（凭证走 ~/.npmrc）
bun run publish:plugin:next
bun run publish:plugin

# ③ 推仓库（含改名、去互斥、0.9.0 版本号、截图声明），然后去 awesome-dsh-plugin 提 PR
```

> ⚠️ `verify:npm:plugin` 需要一棵含 `@deepseek-ai/*` 的宿主模块树。
> 桌面端把宿主装在 `app.asar` 里，`~/.bun/install/global` 那份联接可能是悬空的；
> 这时按 `docs/发布检查与事故恢复.md` 的做法给 `ATR_DSH_MODULES` 指一棵真实模块树
> （可从 `resources/app.asar` 的 `dsh/node_modules` 解出来）。

**PR 标题**：`submission: dsh-plugin-token-report`

**PR 正文模板**：

```markdown
Adds `dsh-plugin-token-report` (Usage & Billing).

- Monorepo subpackage: https://github.com/zhujunzhunzhu/ai-token-report/tree/main/packages/dsh-plugin
  (declares `dsh.bundle` in its package.json; `cordis.patch.yml` ships with the bundle)
- npm: `dsh-plugin-token-report` (repository points back at this repo)
- Installs with: `dsh plugin --profile web add dsh-plugin-token-report`
- It does not register the `sessionTelemetry` service, so it coexists with the built-in
  `dsh-session-telemetry-otel` backend — no profile patch needed.
- Screenshots declared in `packages/dsh-plugin/screenshots.json`.
```

## 6. 合并后的验收

1. 站点重建完成后 `curl -s https://awesome-dsh-plugin.com/plugins.json | grep -c dsh-plugin-token-report` 应 ≥ 1；
2. 市场「发现」页搜 `token-report` → 卡片出现、`npm` 映射生效（显示版本号与下载量）、宿主要求显示为兼容；
3. 在一台干净机器/干净 profile 上 `dsh plugin --profile web add dsh-plugin-token-report`：
   **宿主能起来**（官方 OTel 保持开启）、面板出数、填服务端地址 + appKey 后开始上报；
4. 卡片上的「能力清单」出现 `network` / `fs-read` / `fs-write` / `env` 属预期（静态扫描的披露，不是判决）。

## 7. 上架之后

- **发版即更新**：市场按 npm 版本对比检测更新，改完发新版即可，不必再动列表。
- **截图**：改自己仓库的 `screenshots.json` 即可，下一次站点构建自动生效（不用提 PR）。
- **收录不是永久的**：仓库消失、归档或长期停更会被定期扫描清理下架。
- **下架/回滚**：把那条 YAML 删掉再提一个 PR 即可；npm 包**不要删** —— 它是唯一可用的安装面。

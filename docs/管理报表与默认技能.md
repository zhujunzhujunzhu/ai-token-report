# 管理报表与默认技能

## 管理者要回答的问题

平台已经能统计用量。管理报表应把这些数据组织成可用于资源安排、成本复盘和治理的证据。每次报告先明确“这份报告要支持什么决定”，再选择时间、范围、维度和展示。

| 管理问题 | 需要的证据 | 能支持的决定 | 不能仅凭 Token 推断的结论 |
| --- | --- | --- | --- |
| 最近使用规模如何变化？ | 总量、四类 Token、调用与会话、逐日趋势、明确的比较窗口 | 哪些时间或业务方向需要进一步复盘 | 峰值原因、业务产出增长 |
| 钱主要花在哪里？ | 已计价费用，按币种分开；供应商、模型和项目分布；未计价提示 | 优先核对哪些模型价格与项目投入 | 实际账单、缺价格时的总成本、未提供预算时的超预算 |
| 哪些团队或人员在使用？ | 已入库的人员、分组、客户端来源分布 | 哪些范围值得访谈、培训或核对采集配置 | 全员采用率、个人绩效、未入库等于未使用 |
| 哪些项目占用资源？ | 查询期项目归一化后的用量与估算费用 | 项目投入复盘、规则完善 | 单位产出成本、项目 ROI |
| 模型与平台如何选择？ | 模型、供应商、来源的使用结构和趋势 | 确定需要评测或规范的候选范围 | 没有质量、延迟和任务难度时的“最划算模型” |
| 缓存与上下文是否值得优化？ | 未缓存输入、缓存读写、服务端命中率，按模型/供应商/来源分布 | 选择需要进一步验证的会话或配置 | 命中率低的原因、缓存杠杆等于节省金额 |
| 这份报表可以信到什么程度？ | 已入库来源、未归属、时间窗、最近事件、价格缺失、分页和截断 | 先补采集、身份或价格，再做业务结论 | 从现有数据直接得到完整覆盖率 |

高用量既可能对应重要投入，也可能对应重复尝试。低用量既可能是工具更高效，也可能是采集缺失。报表把观察、可能的解释和待验证行动分别写清楚，不能直接给人打分。

## 时间与维度

时间支持今天、昨天、本周、上周、本月、上月、今年、去年、最近 7/30/90 天和明确起止日期。周报默认回顾完整上周，月报默认回顾完整上月，避免把未完成周期直接当完整周期。自定义日期包含结束当天；统计窗口由后端解析。

比较必须说明两期的实际起止时间。不同天数、节假日、人员范围、采集来源和价格变更都会影响解释。没有基准时只报告当前事实；若用户提供比较周期，就保留两期原始值。同比、环比百分比和预算预测需要额外明确口径，不能让模型临时心算成为另一套公式。

当前维度为人员、分组、项目、模型、供应商、客户端来源、日期。部门是当前账号授权范围，分组通过成员多对多关系展开。模型/供应商规则按查看者解析，项目由已有归一化规则折叠。人员按完整姓名解析稳定 ID，同名要求澄清。

当前管理报表最多同时提供三个独立分布章节，配合总览、日趋势、可选比较与诊断。它们观察同一批用量，不能把各章节再相加；这也不是任意维度交叉透视表。项目目前可作为分布维度，尚没有项目名称查询筛选，不能声称已经只查指定项目。

## 已落地的默认技能

截图中的部门看板 AI 助手是本次入口。输入框输入 `/`，显示下面的默认技能；也可输入中文搜索。上下键移动，Enter 或 Tab 填入可编辑草稿，Esc 关闭。选择不会直接发送，用户可以先修改时间、人员、维度和文件格式。草稿和排队发送沿用现有会话实现。

| 命令 | 用途 | 默认时间 | 默认分布 |
| --- | --- | --- | --- |
| `/report` | 综合管理报表 | 最近 7 天 | 人员、项目、模型 |
| `/weekly` | 管理周报 | 完整上周 | 人员、项目、来源 |
| `/monthly` | 管理月报 | 完整上月 | 分组、项目、模型 |
| `/cost` | 费用分析 | 完整上月 | 供应商、模型、项目 |
| `/adoption` | 使用分布 | 最近 30 天 | 人员、分组、来源 |
| `/cache` | 缓存分析 | 最近 7 天 | 模型、供应商、来源 |
| `/quality` | 数据质量 | 最近 7 天 | 来源，并附采集诊断 |

直接发送 `/weekly` 使用默认条件。自然语言也可调用同一报表工具，不强制记住命令。明确的用户条件始终优先于技能默认值。例如：

```text
/monthly 生成2026年9月的管理月报，按分组、项目和模型，导出 Excel。
/report 生成2026-09-01到2026-09-15的报表，只看朱俊，按模型和来源，导出 HTML。
/cost 生成上月费用分析，与本月对比，说明两个窗口是否完整，不计算未经定义的环比。
/cache 分析最近30天模型与来源的缓存表现，给出待验证建议。
```

报表默认生成私有 HTML 下载文件，可改为 Markdown、Word 或 Excel。Excel 每个章节独立工作表；各格式保留真实数据与查询说明。单表 CSV 继续使用原来的数据集导出。生成文件不自动分享，分享仍遵循现有显式授权与到期规则。

默认报表给出已授权真实数据和证据边界，助手可据此撰写发现与建议。确定性导出文件目前主要是指标、数据表和来源说明；助手的解释在对话中呈现，不把模型生成的数字或未验证解释混入统计文件。

## 数据与执行边界

- 数据仍来自部门统计 API，不新增日志采集、不重算 Token 或金额。总量包含未缓存输入、输出、缓存读、缓存写；reasoning 是输出子集。
- 非管理员仍只能查询本人；技能不能扩大范围。同名、不存在、无权限或任一章节查询失败时，不生成部分报告冒充完整报告。
- 没有 `cost:read` 时只提供用量，并说明费用未授权；有权限也要保留未计价与多币种语义。金额是配置单价计算的估算，不是财务账单。
- 汇总和日趋势最多 366 天；逐条明细和小时查询最多 31 天。数据集保存最多 400 行，模型仅预览前 12 行，导出保留实际返回行数、总行数、分页和截断说明。
- 多次查询冻结同一时间边界，但活跃上报期间各节仍是独立读取快照；报表保留每节采集时间，不声称事务级一致快照。
- 分组多对多，各组不可加总成部门总量。诊断最近事件时间不是最近上报时间；`identityViolations` 是结构性值，不包装成逐条检验通过。
- 默认技能是只读查数和私有导出，不隐含管理配置变更、公开发布或向外部服务发送报告。

## 后续能力的优先级

| 优先级 | 能力 | 先补齐什么 |
| --- | --- | --- |
| P1 | 保存个人报表模板、复用相同条件 | 模板归属、版本、筛选恢复与重新鉴权 |
| P1 | 标准同比/环比、完整周期和同期进度比较 | 统一日历与部分周期规则，共享计算和零基准语义 |
| P1 | 自动周报/月报、到期提醒 | 调度、报告接收范围、失败通知、发送授权；本次没有自动创建计划 |
| P2 | 预算使用进度与预警 | 项目/团队/币种预算、有效期、未计价覆盖与阈值 |
| P2 | 使用采用率和采集覆盖率 | 明确的应采人员/客户端名单，在线与采集状态 |
| P2 | 项目与多维交叉分析 | 项目筛选、稳定项目目录、组合维度和非加性会话口径 |
| P3 | 模型评测、单位任务成本与 ROI | 任务类别、质量、延迟、产出和人工投入基准 |

先把“每次同样的问题能得到同样口径、可核对的报告”做好，再引入预算、自动化和效益衡量。

## 实现与验收入口

默认目录在 `packages/shared/src/assistant-skills.ts`，前端菜单消费同一份目录。服务端 `assistant/skills.ts` 解析受维护的命令与指引，`assistant/reports.ts` 注册确定性管理报表工具，复用 `queryUsage`、`AssistantDatasets` 和私有 `AssistantArtifacts`。完整技能工作说明在 `.agents/skills/management-reports/SKILL.md`。

运行助手相关单测、全仓类型检查、两个 Web 构建、部门前端 SSR 验证。前端实际验收覆盖 `/` 展示七项、键盘只填草稿、中文搜索、Esc 关闭和浮窗小尺寸。服务端使用隔离合成数据核对各节数字、窗口、授权、同名失败与多格式导出。

真实模型专项验收在仓库根目录执行：

```powershell
bun --env-file=.env run packages/server/verify/verify-assistant-reports-live.ts --check
bun --env-file=.env run packages/server/verify/verify-assistant-reports-live.ts
```

`--check` 只检查配置，不调用模型。实跑使用隔离 SQLite 与合成用量，执行两条中文请求：指定月份、项目与来源的 Excel 月报；指定月份、模型与供应商的私有 HTML 费用分析。逐节对照数据库与导出单元格，检查匿名下载拒绝、无公开分享与会话持久化。每条请求只执行一次，不自动重跑；摘要和合成文件保存在 `.artifacts/assistant-reports-live/`，临时服务和数据库随后清理。

2026-10-10 本地真实模型验收两条均通过，准确选中 2026 年 9 月窗口并排除 10 月哨兵数据。此次功能尚未部署线上；发布后仍需检查目标环境的模型配置、权限和前端静态资源版本。

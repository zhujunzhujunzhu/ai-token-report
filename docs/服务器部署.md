# 部门服务端部署

把本仓的服务端与看板产物送到 `117.72.173.21` 的 `/ai-token/` 下。
入口是 `scripts/deploy-server.mjs`（**Node 脚本**，`node` 直接跑，不需要 bun 做入口）。

> ⚠️ 这与 [`scripts/release.ts`](发布检查与事故恢复.md)（npm 公开发布）是**两件事**：
> 前者把产物送上网关机器，后者把 tarball 发到 registry.npmjs.org。
> 两者的验证范围没有交集，**不要互相替代**。

---

## 一、三个档位（默认零副作用）

```bash
bun run deploy:server              # dry-run：只本地构建 + 打包 + 打印计划，不连服务器
bun run deploy:server:preflight    # 真上传到服务器 /tmp 并校验产物，不切换、不重启
bun run deploy:server:apply        # 真部署：备份 → 切换 → 重启 → 健检，失败自动回滚
```

也可以直接跑脚本本体（便于加参数）：

```bash
node scripts/deploy-server.mjs --apply --skip-verify      # 跳过本地测试（构建仍会跑）
node scripts/deploy-server.mjs --apply --full-verify      # 额外跑全仓 bun test + typecheck
node scripts/deploy-server.mjs --apply --keep-old-assets  # 不清理历史 assets
```

| 参数 | 作用 |
|---|---|
| `--apply` / `--preflight` / `--dry-run` | 三档互斥；**不带参数 = dry-run** |
| `--skip-verify` | 跳过本地 typecheck 与 server 测试 |
| `--full-verify` | 改用全仓 `bun test` + `bun run typecheck` |
| `--keep-old-assets` | 保留看板历史 assets（默认清理） |
| `--server` / `--user` / `--hostkey` / `--portal-base` / `--remote-root` | 覆盖默认值 |

默认档位下脚本**不产生任何远程影响**；`--preflight` 只写 `/tmp`；只有 `--apply` 会动现网。
每次运行在 `.artifacts/deploys/<时间戳>/` 留 `report.json`、逐步日志、两个 tarball、
生成的远端脚本 `remote.sh` 与远端输出 `remote.log`。

## 二、它到底做了什么

| 阶段 | 动作 |
|---|---|
| 本地验证 | 默认：server typecheck + `bun test packages/server`（含 67 项 HTTP 契约）+ web-portal typecheck |
| 本地构建 | `build:node` → `packages/server/dist/*.mjs`；`DSH_PORTAL_BASE=/ai-token/ bun run build:portal` |
| 产物断言 | 三个 `.mjs` 都在；`index.html` 必须含 `/ai-token/assets/` |
| 打包 | `tar -czf` 两份，记录 sha256（传的与解的是同一份字节） |
| 上传 | 传到服务器 `/tmp/atr-deploy-<stamp>-{server,portal}.tgz` |
| 远端校验 | 解包到 staging，断言文件齐全 + **index.html 前缀正确**，否则拒绝切换 |
| 切换 | 先备份到 `.deploy-backup-<stamp>`，再替换两个 `dist` |
| 重启 | 加载 `/root/.atr/portal.env`，`pm2 restart ai-token-server` |
| 健检 | 30 秒内轮询 `127.0.0.1:$ATR_PORT/api/health`；失败**自动回滚**并打印 PM2 日志 |
| 公网校验 | 抓 `http://<host>/ai-token/health`、首页、入口 JS，断言 MIME 是 `javascript` |

> 最后一条是**唯一能抓住「白屏」的环节**：子路径配错时资源被站点根的其他应用接走，
> 回 `text/html`，浏览器按模块 MIME 校验拒绝执行 —— 页面全白，而服务端日志里一句错都没有。

## 三、只碰这两个目录（★ 硬边界）

```
/data/ai-token-report/packages/server/dist/         ← 覆盖
/data/ai-token-report/packages/web-portal/dist/     ← 覆盖（含清理历史 assets）
```

**绝不触碰**：

| 路径 | 为什么 |
|---|---|
| `packages/server/node_modules/` | 产物 `external: ['mysql2/promise']`，靠它解析（实测 `MYSQL2_OK`）；`node_modules` 顶层没有 `mysql2`，只有 `packages/server/node_modules` 里有 |
| `deploy/atr-server-start.sh` | 服务器的 PM2 启动包装，**仓库里没有这个文件**，删了服务就起不来 |
| `/root/.atr/portal.env` | 凭证与监听配置，脚本只读取 `ATR_PORT` |
| 上报库 | schema 迁移**不在部署脚本内**，见 §五 |

## 四、子路径部署（`DSH_PORTAL_BASE`）

页面挂在反代子路径 `/ai-token/` 下，构建时**必须**带前缀。脚本默认值就是 `/ai-token/`，
且在构建后立刻断言 `index.html` 里有它 —— 忘了带会构建出绝对路径产物，
**页面立即变白且服务端不报任何错**，所以这条不再依赖人的记忆。

根路径部署用 `--portal-base /` 覆盖。

## 五、数据库迁移是另一件事

上报库（MySQL 8 @3308）是全员数据的**唯一副本**，schema 变更**绝不自动执行**：
版本不符时服务端拒绝普通业务写入，只能显式跑 `dist/migrate-db.mjs`（`inspect` / `migrate` / `resume`）。

部署成功后脚本会比对「服务器 health 里的 `schema_version`」与「本地版本常量」，不一致时**告警**
（当前常量 = **7**，真源是 `packages/core/src/db/portal-schema-v5.ts` 的 `PORTAL_SCHEMA_VERSION`）。
**v4 是冻结基线**：v3 库先迁 v4，再走 v4→v5；v4→v5 会去掉事实表的分组 ID 列
并把 `dept` 改名 `group_name`，SQLite 分支因此必须重建事实表 —— **先按备份流程执行**。
v6 / v7 都**只增表**（`provider_alias`、`model_price` 与各自的权限码），不改既有列。
改了 schema 就必须先迁移再部署，见 [数据库部署与迁移](数据库部署与迁移.md)。

> ✅ **已修**：`scripts/deploy-server.mjs` 现在**不再写死某个版本的文件名** ——
> 它扫描 `packages/core/src/db/portal-schema-v*.ts`，取真正导出 `PORTAL_SCHEMA_VERSION`
> 的那一个（改名前它写死 `portal-schema-v4.ts`，常量搬到 v5 后静默取不到值，
> 而调用点的 `expected !== null` 判断会把「读不到」当成「跳过比对」，
> 这条唯一的版本护栏就消失了）。同时「读不到期望版本」现在会**显式告警**，
> 不再静默跳过。

## 六、连接方式与前置条件

脚本按顺序二选一，**优先免密**：

1. **OpenSSH 免密**（`ssh -o BatchMode=yes` 能过）→ 用 `ssh` / `scp`；
2. 否则用 **PuTTY 的 `plink` / `pscp`**（OpenSSH 客户端不接受命令行密码，密码那条路只能走它）。

密码与主机取自仓库根 `.env` 的 `host` / `password`，可用环境变量
`ATR_DEPLOY_HOST` / `ATR_DEPLOY_USER` / `ATR_DEPLOY_PASSWORD` / `ATR_DEPLOY_HOSTKEY` 覆盖。
主机指纹自动从 `~/.ssh/known_hosts` 推导（缺了它会表现为「密码对但连不上」）。

> 🚨 **指纹形式必须是裸 MD5 冒号**（`ab:cd:…`），**不是** `ssh-keygen -lf` 默认输出的
> `SHA256:…`。实测 PuTTY 0.72：`-hostkey SHA256:…`（含 `ssh-ed25519 255 SHA256:…` 变体）
> 一律 `not a valid format for a manual host key specification`，pscp 在**上传阶段**就失败，
> 密码那步都走不到 —— 症状是「明明 .env 里有密码，却卡在上传」。脚本已改用
> `ssh-keygen -l -E md5` 生成 MD5 形式（新旧 PuTTY 都接受）；手工传 `--hostkey` 时也请给 MD5。

前置：本机 `bun`、`node ≥ 20`、`tar`，以及 `plink`+`pscp`（或免密 ssh）。

> 建议把 `~/.ssh/id_ed25519.pub` 装到服务器 `authorized_keys`，之后就是免密路径，
> 不必再让密码出现在进程命令行里。

## 七、回滚

自动回滚发生在**远端同一个脚本内**（健康检查 30 秒不过即还原并重启），
所以本地网络中断也不会留下「切了一半」的状态。

手工回滚（用自动备份）：

```bash
TS=<时间戳>   # 见部署输出里的 .deploy-backup-<TS>
cd /data/ai-token-report
rm -rf packages/server/dist && cp -a .deploy-backup-$TS/server-dist packages/server/dist
rm -rf packages/web-portal/dist && cp -a .deploy-backup-$TS/portal-dist packages/web-portal/dist
export PATH=/usr/local/bin:$PATH && pm2 restart ai-token-server
```

## 十、实测记录（2026-09-30 复部署）

本次把服务端与看板重新发布到 `117.72.173.21`（`schema_version` 7 → 7，**未涉及数据库迁移**：
服务器 health 与本地 `PORTAL_SCHEMA_VERSION` 都是 7）。两台都是 7 时部署纯粹是产物替换。

| 结论 | 验证方式 |
|---|---|
| PuTTY 0.72 只认**裸 MD5 冒号**指纹 | 六种写法逐个试：`SHA256:` / `类型+位+SHA256` / `MD5:` 前缀 / `0x` 公钥字节全部 `not a valid format`；只有裸 MD5（`b8:92:…:c5`）走到 `Access denied`（= 指纹已通过，密码是故意填错的）。脚本据此改用 `-E md5` |
| 本机 `HTTP_PROXY` 末尾的 LF 会让**构建直接崩** | `bun run build:portal` → `ERR_PROXY_INVALID_CONFIG`（Node 构造 http Agent 时抛）。⚠️ **Bun 从注册表（Machine 级）读这两个变量**：进程内改写无效，只能删除该变量或修机器级配置 —— 即 `Remove-Item env:HTTP_PROXY, env:http_proxy` 对 `bun` 这条链路才有效 |
| 部署成功 | old pid `28182` → new pid `30443`，health `ok:true`，公网入口 JS `200 text/javascript`，历史 assets 清理 45 个，未触发回滚 |
| 备份位置 | `/data/ai-token-report/.deploy-backup-2026-09-30T14-46-31-740Z` |

> ⚠️ 部署产物取的是**工作区当时的状态**（本仓 `deploy:server` 不检查 git 干净与否）。
> 本次工作区有另一个写者在并发编辑（`packages/shared`、`packages/server`、`packages/web-portal`
> 在 apply 前后数秒内仍在写入），第一次 apply 正是因此在 `web-portal` 类型检查处中止。

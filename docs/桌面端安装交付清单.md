# DSH Desktop（桌面端）插件安装交付清单

- **目标**：在同事的 **DSH Desktop** 上装出 `dsh-plugin-token-report` 的用量面板，并按需开启团队上报
- **适用插件版本**：`>=0.7.0`（npm `latest`；`0.6.0` 及更早钉死了精确 peer，见 §1.3）
- **核对日期**：2026-09-30（npm registry 与仓内文档；**本文的 Desktop 路径与 generation 行为来自文档实测记录，未在本机复跑**，见 §8）
- **状态**：步骤可用；macOS / Linux 的宿主入口路径**待实测**（§7）

> 🚨 **交付前先读完 §0 与 §1.3**：这个插件装错的典型症状是
> **「界面没有面板 + 一条也不上报」，而且不报错**。不知道这一点的人会去翻网络和数据库，方向全错。

---

## 零、结论先行

| 问题 | 答案 |
|---|---|
| 能不能在 Desktop 界面里点一下装好？ | ❌ **不能**。侧边栏「插件」是社区市场 `dshmarket`，它只接受 [awesome-dsh-plugin](https://awesome-dsh-plugin.com) 精选列表内的来源；本插件不在其中（实测其 `plugins.json` 中 `token-report` **0 命中**）。 |
| 那怎么装？ | 走命令行。与命令行版 DSH **同一条装配路**，只是 home / profile / pnpm 换成 Desktop 自己的。§2 |
| 要不要重新填身份 / appKey？ | **不要**。数据目录缺省 `~/.ai-token-report`，与命令行版**共用**，Desktop 里不会再出现「尚未署名」。§4 |
| 会话日志会只看 Desktop 的吗？ | 不是。缺省统计**本机全部 DSH 的并集**，镜像会话按 `event_id` 去重。 |
| 唯一的界面化一键装途径？ | 把包 PR 进 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 精选列表（长期项，非本次交付范围）。 |

## 一、前置条件

### 1.1 环境

| 项 | 要求 | 怎么确认 |
|---|---|---|
| DSH Desktop | 已安装且**能正常启动过一次**（先让它把 profile 建出来） | 启动到界面出现 |
| 随包 Node | ≥ 22.15.0（Desktop 自带，本机实测 v24.9.0） | 步骤 ② 之后 `node -v` |
| 网络 | 能访问 npm registry（装 tarball 时不需要） | — |
| 插件版本 | `@latest`（当前 `0.7.0`） | `npm view dsh-plugin-token-report version` |

### 1.2 需要的凭证（只在上报时需要）

- **`appKey`**：管理员在部门平台「appKey 管理」页签发。**没有它插件不会上报**（合规底线，代码硬保证）。
- **服务端根地址**：例如 `https://portal.example.com` 或自建 `http://127.0.0.1:8787`。
  上报地址由它推导（`<地址>/api/v1/token-usage`），**不要自己拼路径**。

> 只在自己机器上看用量（面板 / 数字）**不需要 appKey、也不需要署名**。

### 1.3 🚨 版本窗口 —— 装错版本会**静默不生效**

宿主启动时由 `dsh-app-boot` 的 `evaluatePluginCompatibility` 逐个 `@deepseek-ai/dsh*` peer 做
`semver.satisfies(runtime, range, { includePrerelease: true })`，
**任一不满足就跳过整个 bundle**，日志只有一行 `skipping profile bundle …`（**不是报错**）。

| 插件版本 | 声明的 peer 窗口 | Desktop（自带 `0.1.7-rc.2`） |
|---|---|---|
| `0.6.0` 及更早 | 精确 `0.1.7-rc.2` | ✅ 能跑，但 Desktop 一升版就被跳过 |
| **`0.7.0`（当前 `latest`）** | `>=0.1.7-rc.2 <0.3.0-0` | ✅ 推荐；同时接受 `0.2.x` |

- **装 `@latest` 就对了**，不需要为了拿放宽窗口去手工打 tarball（tarball 只在装未发布版本时才用，见 §2 ③）。
- Desktop 升到 **`0.3.0` 及以后**会被跳过。届时：等插件放宽并复验，或
  `dsh plugin allow-version dsh-plugin-token-report@<版本> --dsh-version <版本> --accept-risk`
  （**自担风险，不等于已验证**）。

## 二、安装步骤

### ① 完全退出 DSH Desktop

要写 profile 与 `node_modules`，**含托盘图标一起退**。装完之前不要启动它。

### ② 开一个 PowerShell，把 home、宿主入口、Desktop 的 pnpm 都指过去

```powershell
# 安装目录按目标机器实际替换
$desktopRoot = "D:\Program Files\DSH Desktop"
$desktopDsh  = "$desktopRoot\resources\app.asar.unpacked\node_modules\@deepseek-ai\dsh\lib\bin.js"

$env:DSH_HOME = "$env:APPDATA\dsh-desktop\harness"
$env:PATH     = "$env:DSH_HOME\.desktop-bin;$env:PATH"   # ★ 用 Desktop 自己的 pnpm / node

# 自检：node 与宿主入口都在
node -v
Test-Path $desktopDsh
```

> `PATH` 这行**不是可有可无**：Desktop 的 `pnpm.cmd` 会在 pnpm 跑动期间临时排除 generation 投影，
> 换成系统里那个 pnpm 就绕开了这层保护。同时 `.desktop-bin` 里是 Desktop 自带的 Node
> （实测 `%APPDATA%\dsh-desktop\harness\.desktop-bin\node.cmd`），版本要求一并满足。

### ③ 装包

```powershell
# 常规：npm 稳定版（当前 0.7.0，peer 窗口已放宽）
node $desktopDsh plugin --profile web add dsh-plugin-token-report@latest
```

只有装**未发布 / 离线**版本时才用 tarball：

```powershell
# 先在仓里打包（只打包、不发布），tgz 落在 .artifacts/releases/<时间戳>/
bun run publish:plugin:dry

# ★ 路径用正斜杠（反斜杠会报 ERR_UNSUPPORTED_ESM_URL_SCHEME），并按你仓的实际位置替换
node $desktopDsh plugin --profile web add file:D:/Coding_agent/ai-token-report/.artifacts/releases/<时间戳>/dsh-plugin-token-report-0.7.0.tgz
```

`add` 会自动把包名登记进 `profiles/web/package.json` 的 `dsh.profile.bundles` ——
**不要再手动 `insert`**。落地后形如：

```json
{ "dsh": { "profile": { "bundles": [
  "@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-plugin-token-report" ] } } }
```

### ④ 合并 OTel 禁用

编辑 `%APPDATA%\dsh-desktop\harness\profiles\web\cordis.patch.yml`
（从 `~/.dsh` 导入过配置的机器通常已经有了）：

```yaml
# 同一时间只能有一个 sessionTelemetry 后端。
- id: session-telemetry-otel
  disabled: true
```

> 不关会**直接启动失败**：`service "sessionTelemetry" has been registered at <OpenTelemetrySessionBackend>`。
> 该后端默认 `mode: FEEDBACK_ONLY`，关掉不影响任何本地功能。

### ⑤ 只读核对（不起服务）

```powershell
node $desktopDsh plugin --profile web list                # 期望看到 dsh-plugin-token-report@0.7.0
node $desktopDsh --profile web --dump-config | Select-String token-report
```

### ⑥ 启动 Desktop

启动到界面，**选择工作区**后，输入框上方出现 `TOKEN 用量` 条即装好。

- 默认位置（`dock`）= **只有输入框上方那条**；要让它在会话标题栏右上角、或两处都要，
  在面板右上角齿轮「配置」→「面板位置」改，**保存即生效**，不必重启。
- Desktop 只暴露 `web` 这一个 profile 名，别的名字直接抛错。

## 三、验收：三个证据（外加一个独立旁证）

桌面端**看不到宿主的终端输出**，它写在 `%APPDATA%\dsh-desktop\logs\harness.log`。

| # | 证据 | 怎么看 |
|---|---|---|
| 1 | 数据通道已挂载 | 日志里应有 `UI 用量面板数据通道已挂载 → GET /api/tokenReport.stats（面板位置：…）` |
| 2 | 本次启动的完整地址 | 同日志里 `dsh web: http://127.0.0.1:<端口>/?token=…` |
| 3 | 界面确实有面板 | 输入框上方那条；点「详情」能打开弹框并出数（首次建索引可能十几秒） |

想确认数据通道真的在跑（`/api` 前有 `Host`/`Origin` 栅栏 + cookie 校验，所以要带上）：

```powershell
$url = "http://127.0.0.1:<端口>/?token=<日志里那串>"
$jar = "$env:TEMP\dsh-cookies.txt"
curl.exe -s -o NUL -c $jar $url
curl.exe -s -b $jar -H "Origin: http://127.0.0.1:<端口>" "http://127.0.0.1:<端口>/api/tokenReport.config"
# 期望：200 + {"position":"dock"}
```

> 另一个**独立**证据：启用后**数据目录**下会出现 `outbox/` 目录（缺省 `~/.ai-token-report/outbox`）。
> 未启用（未署名 / 没 appKey / `features.reporting: false`）时**不会创建** —— 这是「后端真的构造了」的最直接证据。

## 四、首次使用与团队上报

在详情面板右上角齿轮「配置」里填**五个字段**：

| 字段 | 说明 |
|---|---|
| 服务端地址 | 部门平台根地址；上报地址由它推导 |
| appKey | 管理员签发的那一串。**已配置时留空 = 只改下面三项偏好**（不重新校验、不重写身份文件） |
| 上报间隔 | 5 秒 / 10 秒（默认）/ 30 秒 / 1 分钟 / 5 分钟 —— 直接决定服务端请求密度，只给档位 |
| 面板位置 | `dock` / `header` / `both`，保存后**就地**换地方 |
| 会话日志根 | 每行一个 DSH home；**留空 = 自动发现本机全部 DSH**（缺省行为）。改了**保存即生效**，输入框下面那行会列出当前真正在读的根 |

> 会话日志根是「统计哪几处日志」，与会话日志根无关的**数据目录**（身份 / 库 / outbox）
> 面板里**没有**：那要改 `dataDir`（部署配置或 `DSH_TOKEN_REPORT_DATA_DIR`），
> 见 §4 末的风险提示。

点「验证并保存」后，插件拿该 appKey 请求 `<地址>/api/v1/identity/verify`，
**姓名与分组以服务端返回值为准**（面板不问姓名 —— 由 appKey 在服务端绑定的人决定）。
**保存即生效，不必重启**，并当场开始补报本机全部历史用量。

排查「部门看板上没有我的数」看**「上报调试」**页签：状态与原因、计数、最近请求体原文与回执、
补报进度，外加「立即上报一次」与「不发送预览」两个按钮。

> 🚨 页面里**看不到 appKey**（宿主只留请求体、不留请求头）—— 这是刻意的，不要为了排查把请求头加进去。

### 身份 / 配置 / 库在哪

| 路径 | 内容 |
|---|---|
| `<dataDir>/identity.json` | 署名（token 就是 appKey） |
| `<dataDir>/plugin-connection.json` | 面板里填的地址 / appKey / 间隔 / 位置 / 会话日志根 |
| `<dataDir>/usage.sqlite` | 本地增量索引库（日志的派生物，**可删可重建**） |
| `<dataDir>/outbox/` | 磁盘 outbox（崩溃不丢） |
| `<dataDir>/backfill/<scope>/` | 历史补报水位 |

`<dataDir>` 缺省 **`~/.ai-token-report`**，**与会话日志根无关** ——
所以 Desktop 与命令行版**缺省共用同一份身份**，不需要任何配置。

> 🚨 **不要用 `dshHomes` 去达到「分开身份」的目的**：它换的是**日志来源**，
> 会让面板少算另一套 DSH 的会话，而实时上报照常工作 ——
> 这个错误**不会**以「完全没数据」的形式暴露。要分开身份用 `dataDir`（或 `DSH_TOKEN_REPORT_DATA_DIR`）。

## 五、升级 / 卸载 / 回滚

### 5.1 升级

**走同一条 `add` 路**（重复执行 §2 ③ 即可换版本）。

> 🚨 不要只手改 `profiles/web/package.json`：Desktop 启动时会做 profile maintenance，
> 把非市场来源的插件迁成**不可变 generation**（`.generations/live/<...>`，一次 rename 上线），
> 并写 `dsh.desktop.generationProjection` 与 `pnpm.overrides`。进了 generation 之后，
> **只有重新 `add` 才换得了版本**。

### 5.2 卸载

```powershell
node $desktopDsh plugin --profile web remove dsh-plugin-token-report
```

`remove` 会走 Desktop 自己的 generation 下线流程；随后把 §2 ④ 的 OTel `disabled: true` 改回，
并按需删掉数据目录里的 `outbox/`（`usage.sqlite` 是本地页与 CLI 共用的派生物，按需保留）。

> ⚠️ `plugin remove` 这一条**未实测**（仓内文档只提到它会走 generation 下线流程）。
> 若它报错或行为不符预期，就退回手动方式：先从 `profiles/web/package.json` 的
> `dsh.profile.bundles` / `dependencies` 里去掉包名，再处理 generation（不要手改
> `.generations/` 里的内容），最后重启 Desktop 确认。

### 5.3 症状 → 回滚

| 症状 | 先做什么 |
|---|---|
| 启动失败、报 `sessionTelemetry` 已注册 | 确认 OTel 已 disable，且插件没有被挂两次 |
| 面板不见了 + 一条也不上报 | 数 `skipping profile bundle`（§1.3）；再看 generation 是否被冻结（§6） |
| 装完全都正常但部门看板没数 | 看「上报调试」页签给的原因，再看 `token_usage_diagnostics` 的补报进度 |

## 六、排障表

| 现象 | 原因 | 处理 |
|---|---|---|
| 界面里搜不到本插件 | 市场只收 awesome-dsh-plugin 精选列表内的来源 | 走 §2 命令行 |
| `skipping profile bundle "dsh-plugin-token-report": … is incompatible with dsh <版本>` | peer 与当前宿主不同代（§1.3） | 装 `>=0.7.0`；或 `allow-version … --accept-risk`（自担风险） |
| **什么都不打印、界面也没面板** | 包不在 profile 的解析范围内，或 `features.ui: false` | 核对 §2 ⑤ 的两条只读命令；确认 `features.ui` 没被关 |
| 数据通道那句有，但界面没面板 | 浏览器半没被加载 —— `dsh.client` 声明缺 `exports["./client"]`，或产物文件不存在 | **重新构建/重装插件**；这一条会让 DSH 启动直接失败（`ClientPackageCompositionError`），不是「面板不出现」 |
| 启动日志出现 `.generations-deferred.json` | generation 迁移失败，该迁移被**冻结** | 按文件里的原因处理后再重启；不要手改 `.generations/` 里的内容 |
| `ERR_UNSUPPORTED_ESM_URL_SCHEME` | `file:` 依赖写成了 Windows 反斜杠路径 | 用 `file:D:/...` 正斜杠形式（§2 ③） |
| 401 / 未通过宿主鉴权 | 打开的不是本次启动打印的完整地址 | 用日志里那串带 `?token=` 的地址 |
| 加载即 `ERR_UNKNOWN_BUILTIN_MODULE: bun:sqlite` | 把**仓内源码包**当插件装了 | 只装发布包 / 构建产物（§2 ③） |
| 首次统计较慢 / 显示降级 | 首次建索引；或 SQLite 权限、宿主 Node 版本 | 等索引完成；核对 `node -v` |
| 升级后面板要求重新署名 / 数字少了一块 | 从 `0.5.0` 及更早升到 `0.6.0+` 时**数据目录换了位置** | 手动搬一次家：`~/.dsh/token-report` → `~/.ai-token-report`（插件 README「0.6.0 数据目录位置变更」一节） |

## 七、未实测 / 待补项（如实标注，别当成已验证）

1. **macOS / Linux 的宿主入口路径**：本文只给了 Windows 的
   `<安装目录>\resources\app.asar.unpacked\node_modules\@deepseek-ai\dsh\lib\bin.js`。
   macOS 的 home 已知是 `~/Library/Application Support/dsh-desktop/harness`，
   但 `.app` 包内 `bin.js` 的实际路径**本文没有实测过**，不猜。
2. **桌面端上游「插件」管理页**（`@deepseek-ai/dsh-plugin-manager`，接受 npm 包名 / 本地路径 / tarball / git）：
   在 Desktop 上包操作归 Desktop shell 所有，会走 generation 管线 —— **未实测**。
3. **Desktop 自带宿主版本**：本文按实测记录（`@deepseek-ai/dsh` = `0.1.7-rc.2`、
   `@deepseek-ai/cordis` = `4.0.4`、随包 Node `v24.9.0`）判断兼容；Desktop 升版后要重新核对 §1.3。
4. **本清单未在本机复跑**：核对这台机器上**没有装 DSH Desktop**
   （`D:\Program Files\DSH Desktop` 与 `%APPDATA%\dsh-desktop\harness` 都不存在），
   所以 §2 的每一步都请在目标机器上按 §3 的三条证据验收。
